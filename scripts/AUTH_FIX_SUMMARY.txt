PROBLEM IDENTIFIED:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
❌ Refresh token API was being called on EVERY request
❌ Access token was not being stored in memory
❌ Every request without Authorization header → 401 → unnecessary refresh
❌ Inefficient and incorrect authentication flow

ROOT CAUSE:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
The original API client (lib/api.ts) had two issues:
1. Access token from login/register was not stored
2. Requests didn't include Authorization header
3. Every 401 triggered refresh, even on first request

SOLUTION IMPLEMENTED:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
✅ Store access token in memory (module-level variable)
✅ Add Authorization: Bearer <token> header to all requests
✅ Only call refresh when token actually expires (401)
✅ Prevent infinite refresh loops with retry flag
✅ Clear token on logout

AUTHENTICATION FLOW (CORRECT):
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Step 1: Login/Register
  POST /auth/login
  ↓
  Response: { accessToken: "xyz...", user: {...} }
  Set-Cookie: dsa_refresh=abc...
  ↓
  Client stores accessToken in memory

Step 2: Authenticated Requests (Token Valid)
  POST /conversations
  Authorization: Bearer xyz...
  Cookie: dsa_refresh=abc...
  ↓
  ✅ Success (no refresh needed)
  
  POST /conversations/123/messages
  Authorization: Bearer xyz...
  Cookie: dsa_refresh=abc...
  ↓
  ✅ Success (no refresh needed)

Step 3: Token Expires (after ~15 minutes)
  GET /conversations
  Authorization: Bearer xyz...  ← expired
  ↓
  ❌ 401 Unauthorized
  ↓
  Client detects 401, triggers refresh:
  
  POST /auth/refresh
  Cookie: dsa_refresh=abc...
  ↓
  Response: { accessToken: "new123..." }
  ↓
  Client stores new token in memory
  ↓
  Retry original request:
  
  GET /conversations
  Authorization: Bearer new123...  ← new token
  ↓
  ✅ Success

Step 4: Subsequent Requests
  Use new token, no refresh needed

SECURITY MODEL:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Access Token:
  • Lifetime: 15 minutes
  • Storage: Memory (cleared on page refresh)
  • Transport: Authorization header
  • Purpose: API authentication

Refresh Token:
  • Lifetime: 7 days
  • Storage: HttpOnly, Secure, SameSite cookie
  • Transport: Automatic (cookie)
  • Purpose: Get new access tokens

Benefits:
  ✅ XSS Protection: Refresh token inaccessible to JS
  ✅ CSRF Protection: SameSite cookie attribute
  ✅ Limited Exposure: Access token only valid 15min
  ✅ Token Rotation: Refresh token changes on use
  ✅ Session Tracking: Linked to user in database
